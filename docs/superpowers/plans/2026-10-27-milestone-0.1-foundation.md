# Milestone 0.1 (Foundation + Risk Spike) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pair a Mac and an Android phone with a QR code, keep them connected over mutual pinned TLS 1.3, show phone status in the Mac menu bar, ring the phone from the Mac, and separately prove (or disprove) the Full-mode mirroring path on a real phone.

**Architecture:**
- **Shared protocol.** One `.proto` schema in `/protocol` generates Swift and Kotlin code. Both languages also implement the shared crypto (fingerprints, pairing proof, 6-digit code, rotating ID), the framing and the pairing URI. Each implementation is checked against JSON test vectors made by a stdlib-only Python reference script.
- **Mac.** Core logic lives in a SwiftPM package (`mac/Packages/AMKit`). A thin SwiftUI menu-bar app is generated with XcodeGen.
- **Android.** Core logic lives in pure-JVM Kotlin modules. A thin Compose app runs it in a `connectedDevice` foreground service.
- **Interop test.** A JVM phone simulator and a Swift Mac simulator exercise the real TLS and pairing code against each other.
- **The spike is throwaway.** It lives on its own branch and reuses the official scrcpy-server. Only its write-up merges.

**Tech Stack:**
- Swift 6, SwiftUI/AppKit, Network.framework, CryptoKit, Security.framework.
- SwiftPM dependencies: swift-protobuf and swift-certificates. XcodeGen.
- Kotlin 2.4.21, AGP 9.3.1, Gradle 9.5.0, Jetpack Compose (BOM 2026.09.00), coroutines 1.11.0, kotlinx-serialization, protobuf-kotlin-lite, zxing-android-embedded.
- Python 3 stdlib (test vectors), OpenSSL (test identities), GitHub Actions.

**Spec:** [docs/PRD.md](../../PRD.md), [docs/ARCHITECTURE.md](../../ARCHITECTURE.md), [docs/ROADMAP.md](../../ROADMAP.md). This plan covers ROADMAP §0.1.

## Global Constraints

**Platforms**
- **Mac:** macOS 14 or later, Apple silicon and Intel. Swift 6 language mode.
- **Android:**
  - `minSdk 29` (Android 10).
  - `targetSdk` = latest stable, so **37**. `compileSdk 37`, minor 1 (as in Whittle).
  - Full mode (spike) is Android 11+ only.

**Licensing and dependencies**
- License **Apache-2.0**.
- No GPL code (do not copy KDE Connect). scrcpy reuse keeps its NOTICE/attribution.
- No Google Play Services, ML Kit or Firebase: F-Droid rejects non-free dependencies.

**Privacy**
- No cloud, account, analytics or telemetry. The only network peer is the paired device.
- The app never requests SMS access (`READ_SMS`, `RECEIVE_SMS` and the like are banned from every manifest).
- Each Android permission is requested only when its feature is turned on.

**Connection and security**
- Mutual TLS **1.3 only**, with peers pinned by SHA-256 fingerprint of the certificate DER. Anything else is rejected.
- The pairing secret is **single-use** and **expires after 5 minutes**.
- Bonjour service type `_anmirror._tcp`. The advertisement carries **no personal data**: random instance name, TXT `v` and `r` only.
- A phone connects to **one Mac at a time**. A Mac serves **one phone at a time**.
- Capabilities handshake on connect: `{protocol_version, app_version, capabilities[], setup_level}`. Protocol version is the integer **1**.

**Acceptance targets**
- Pairing in **under 2 minutes** for a first-time user.
- Reconnect **within 10 s** of both being on the same network and awake.
- Status values update **within 30 s** of a change; connected/disconnected is shown immediately.
- Find my phone rings at **full volume, even on silent or Do Not Disturb, until stopped on either device**.

**Strings and accessibility**
- All UI strings are externalized: Mac `Localizable.xcstrings`, Android `res/values/strings.xml`.
- Every control has a VoiceOver/TalkBack label.

**Identifiers** (placeholders until the name/trademark decision, PRD §12; must be final before the first public release)
- Android `applicationId`: `io.github.anmirror.phone`.
- Mac bundle ID: `io.github.anmirror.mac`.
- Kotlin packages: `io.github.anmirror.*`.

## Review Focus

These are the five most likely ways a real person hits a failure that no feature test covers. Each one gets a test in the task named in brackets.

1. **The Mac has several network interfaces, or a VPN is on.** Several hosts may be in the QR code, and the first can be unreachable. Expected: the phone tries each host with a 3 s timeout. If none answers, it shows "Can't reach your Mac. Are both on the same Wi-Fi? Is a VPN on?" It never spins forever. *(Task 6, `connectsViaSecondHostWhenFirstUnreachable`)*
2. **The Mac's IP changed after sleep or a Wi-Fi switch.** The last-known address fails. Expected: the phone falls back to Bonjour discovery and reconnects within 10 s. *(Task 6, `fallsBackToDiscoveryWhenLastAddressFails`)*
3. **A QR code is scanned a second time, or after 5 minutes.** Expected: a clear "This code has expired. Show a new code on your Mac." It doesn't say "wrong code" or fail silently. *(Task 4, `secretIsSingleUse` and `secretExpiresAfterFiveMinutes`; Task 9 maps the error to copy)*
4. **The phone reboots, or a battery saver kills the app.** Expected: the service comes back (`START_STICKY` plus a boot receiver) and reconnects with no user action. It starts only if a Mac is paired. *(Task 9, `bootReceiverStartsServiceOnlyWhenPaired`)*
5. **The connection drops mid-ring, or the user stops the ring on the phone.** Expected: ringing continues until it's stopped on either device. Stopping restores the user's previous alarm volume and DND filter. *(Task 11, `stopRestoresPreviousVolumeAndFilter` and `keepsRingingWhenConnectionDrops`)*

```proto

message Hello { uint32 protocol_version = 1; string app_version = 2; repeated string capabilities = 3;
                SetupLevel setup_level = 4; string device_name = 5; string device_model = 6; }
message Ping {}
message Pong {}
enum ErrorCode { ERROR_CODE_UNSPECIFIED = 0; ERROR_CODE_PROTOCOL_MISMATCH = 1; ERROR_CODE_NOT_PAIRED = 2;
                 ERROR_CODE_BAD_PAIRING_SECRET = 3; ERROR_CODE_PAIRING_EXPIRED = 4;
                 ERROR_CODE_PAIRING_REJECTED = 5; ERROR_CODE_BUSY = 6; }
message Error { ErrorCode code = 1; string message = 2; }

                     GOODBYE_REASON_SWITCHING_MAC = 2; GOODBYE_REASON_SHUTDOWN = 3; }
message Goodbye { GoodbyeReason reason = 1; }

// pairing.proto
message PairRequest { uint32 protocol_version = 1; bytes secret_proof = 2; string device_name = 3; string device_model = 4; }
message PairVerified {}
message PairConfirm { bool accepted = 1; }
message PairComplete { bytes discovery_key = 1; string mac_name = 2; }

// status.proto
enum NetworkKind { NETWORK_KIND_UNSPECIFIED = 0; NETWORK_KIND_NONE = 1; NETWORK_KIND_WIFI = 2;
                   NETWORK_KIND_CELLULAR = 3; NETWORK_KIND_OTHER = 4; }
message StatusUpdate { int32 battery_percent = 1; bool charging = 2; int32 signal_level = 3; NetworkKind network = 4; }
// signal_level: 0..4, or -1 for unknown / no service (always sent explicitly)

// find.proto
message RingRequest {}
message StopRingRequest {}
message RingState { bool ringing = 1; bool may_be_silent = 2; }
```

**Message types** (the envelope's `type` field):

| `type` | Direction | Payload | Channel |
|---|---|---|---|
| `system.hello` | both (phone first) | `Hello` | SYSTEM |
| `system.ping` / `system.pong` | phone → Mac / reply | `Ping` / `Pong` | SYSTEM |
| `system.error` | either | `Error` | SYSTEM |
| `system.goodbye` | either | `Goodbye` | SYSTEM |
| `pairing.request` | phone → Mac | `PairRequest` | PAIRING |
| `pairing.verified` | Mac → phone | `PairVerified` | PAIRING |
| `pairing.confirm` | both | `PairConfirm` | PAIRING |
| `pairing.complete` | Mac → phone | `PairComplete` | PAIRING |
| `status.update` | phone → Mac | `StatusUpdate` | STATUS |
| `find.ring` / `find.stop` | Mac → phone | `RingRequest` / `StopRingRequest` | FIND |
| `find.state` | phone → Mac | `RingState` | FIND |

**Message rules:**
- Envelope `id` counts up from 1 per sender per connection.
- `reply_to` carries the request's `id`, or 0.
- Capability strings in 0.1: `status.v1` and `find.v1`.

**Wire and crypto definitions** (copy into `SPEC.md`):
- **Frame:** a 4-byte big-endian unsigned length, then the `Envelope` bytes.
  - Length 0 is an error.
  - Length over **1,048,576** is an error and closes the connection.
- **Fingerprint:** `fp = SHA-256(certificate DER)`, 32 raw bytes. Shown and stored as lowercase hex. The device ID is that hex string.
- **Secret proof:** `HMAC-SHA256(key = secret, msg = "anmirror-pair-v1" ‖ mac_fp ‖ phone_fp)`. The secret is 32 random bytes.
- **Confirmation code:**
  - `h = SHA-256("anmirror-sas-v1" ‖ mac_fp ‖ phone_fp)`.
  - `code = uint32_be(h[0..4]) mod 1,000,000`, zero-padded to 6 digits.
- **Rotating ID** (Bonjour TXT `r`):
  - `epoch = floor(unix_seconds / 900)`.
  - `r = lowercase hex of HMAC-SHA256(discovery_key, "anmirror-rid-v1" ‖ uint64_be(epoch))[0..8]` (16 hex characters).
  - The phone accepts `epoch − 1`, `epoch` and `epoch + 1`.
- **Discovery key:** 32 random bytes per Mac, sent to the phone in `PairComplete`.
- **Pairing URI:** `anmirror://pair?v=1&fp=<b64url(mac_fp)>&s=<b64url(secret)>&h=<host>,<host>&p=<port>&n=<pct(mac_name)>`.
  - b64url is RFC 4648 §5, no padding.
  - `pct` is RFC 3986 percent-encoding of UTF-8; unreserved characters are kept.
  - Parsing outcomes:
    - Unknown extra parameters are ignored.
    - `v` other than 1 → `unsupportedVersion`.
    - `fp` or `s` that isn't 32 bytes, or a missing `h` or `p` → `malformed`.
- **Pairing sequence** (phone is the TLS client; it pins `fp` from the QR code):
  1. Phone → `pairing.request`. If the protocol version is wrong → `system.error PROTOCOL_MISMATCH`.
  2. Mac verifies the proof, then sends `pairing.verified`. On a bad proof → `system.error BAD_PAIRING_SECRET`. After 3 bad proofs, or once the secret is used or 5 minutes old → `PAIRING_EXPIRED`.
  3. Both sides show the code.
  4. Each side sends `pairing.confirm{accepted}` when its user decides. `false` from either side → both show "Pairing cancelled" and the connection closes. There is a 60 s limit.
  5. When both have accepted, the Mac sends `pairing.complete`. Both persist the peer.
  6. The phone then sends `system.hello` on the same connection.
- **Rules after pairing:**
  - **Unpaired client certificates** are allowed only while a pairing window is open, and their first message must be `pairing.request`. Anything else → `system.error NOT_PAIRED`, then close.
  - **A second paired phone** connecting while one is active → `system.error BUSY`, then close.
- **Keep-alive** (initial value; battery tuning in 0.9):
  - The phone sends `system.ping` every **30 s**. No `pong` within **10 s** → the phone reconnects.
  - The Mac marks the phone lost after **75 s** of silence.
  - On wake from sleep, the Mac closes every connection and restarts its listener on the same port.

### Task S3: Mac viewer with latency and fps harness

- [ ] **Step 1: Build the viewer.**
  - Parse the scrcpy video stream: the codec header (12 bytes: codec id, width, height), then per-packet 12-byte headers (pts with config/keyframe flags, size).

- [ ] **Step 2: Build FlashActivity.** It's a fullscreen activity: black, turning white on `ACTION_DOWN` and back to black on `ACTION_UP`.
- [ ] **Step 3: Build the latency harness.**
  - The viewer sends a scrcpy `INJECT_TOUCH_EVENT` down/up at the screen center and records `t0` (`mach_absolute_time`).

  - Run 100 trials, 500 ms apart. Report median and p95 of `t1 − t0`, a round trip that includes injection.
- [ ] **Step 4: Measure fps** over 30 s while FlashActivity animates continuously, plus while scrolling a long list in Settings.
