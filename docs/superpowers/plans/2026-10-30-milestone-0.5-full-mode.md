# Milestone 0.5 (Full mode: mirroring & control) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On an Android 11+ phone set up once for Full mode, the Mac shows the phone's screen live in a resizable window, with the phone's audio, and the Mac's mouse, trackpad and keyboard (including emoji and non-English input) control it. Back, Home, Recents, rotate, volume and screen-off are one click away, files dropped on the window go to the phone, and the phone's clipboard reaches the Mac automatically while the window is open. Under 80 ms and 60 fps on the reference phones over 5 GHz Wi-Fi, and lower quality, not lag, on weaker links.

**Architecture:**
- **Helper.** scrcpy-server v5.0.1, built from vendored source in a new `:helper` Gradle module (two small patches), shipped in the APK's assets. The phone app pairs with the phone's own Wireless debugging (`libadb-android`), pushes the jar, and starts it as the `shell` user.
- **Relay.** The app opens the helper's three local sockets through its own ADB connection and copies their bytes, unchanged, onto three new bulk connections to the Mac (roles `MIRROR_VIDEO = 4`, `MIRROR_AUDIO = 5`, `MIRROR_CONTROL = 6`) over the 0.3 pinned TLS bulk listener. The Mac speaks the scrcpy v5.0.1 stream and control protocol directly. The phone app opens no listening socket.
- **Control channel.** `mirror.v1` on channel `MIRROR = 18` (SPEC §24): availability, start (with single-use tokens the Mac issues), state, stop, and a test pattern for the delay harness. Only these go through the Mac's `NotifyWorkQueue`.
- **Phone.** Pure logic in a new `feature/mirror` library (pairing replies and errors, maker guidance, the server command, the relay pump, the session state machine). ADB sits in a new `core/adb` library behind `AdbClient`. `AppGraph` and `ConnectionService` wire them with the 0.3 gating pattern.
- **Mac.** A new `FeatureMirror` target: stream parsers, control encoders, VideoToolbox decode into `AVSampleBufferDisplayLayer`, AudioToolbox + `AVAudioEngine` playback, input mapping with `NSTextInputClient`, adaptive quality and the delay harness. The window is AppKit (`mac/App/MirrorWindow.swift`). Every system callback runs in a nonisolated helper.
- **No connection-core logic changes.** `ConnectionManager`, `PhoneSession`, `MacServer` and `ControlConnection` stay as reviewed. `BulkServer` is untouched; the app's `onLink` routes the three new roles.

**Tech Stack:** as 0.4. New:
- **Android:** `libadb-android` 3.1.1 (JitPack, under its Apache-2.0 option), `conscrypt-android` 2.5.3, Bouncy Castle `bcpkix-jdk18on` 1.86, `NsdManager` (via libadb's `AdbMdns`), `RemoteInput`, `Choreographer`; scrcpy-server v5.0.1 source (Apache-2.0). Gson (test only, in `:helper`).
- **Mac:** VideoToolbox (`VTDecompressionSession`, `VTCompressionSession` in the sample generator), CoreMedia, AVFoundation (`AVSampleBufferDisplayLayer` and its `sampleBufferRenderer`, `AVAudioEngine`, `AVAudioPlayerNode`), AudioToolbox (`AudioConverter`), AppKit (`NSTextInputClient`, `NSToolbar`, `NSDraggingDestination`).

**Spec:** [docs/PRD.md](../../PRD.md) (F-17, F-18, F-05 Full, §8–§13), [docs/ARCHITECTURE.md](../../ARCHITECTURE.md) (§6, §3.3, §4, §7, §9, §10), [docs/ROADMAP.md](../../ROADMAP.md) §0.5. Protocol rules: [protocol/SPEC.md](../../../protocol/SPEC.md). Spike evidence (read-only, never copied): branch `spike/full-mode`, write-up `docs/spikes/2026-10-full-mode-spike.md`. The controller's design decisions are binding, and this plan follows them except where the notes below say otherwise. This plan builds on branch `milestone-0.5` at `8cc13a5` (0.1–0.4 complete).

**Where this plan departs from the design notes, and why:**
1. **Spec conflict, flagged for the controller: phone → Mac clipboard is automatic only while the phone screen is shown.** PRD F-05 and ROADMAP 0.5 say "automatic in Full mode". Design decision 9 takes the clipboard from the helper, which runs only during a mirror session (decision 12). A background control-only helper would keep a `shell` process and an ADB link alive all day: a battery cost against the 2%/day goal, and the "helper running after the user turned Full mode off" threat in ARCHITECTURE §7. This plan follows the design notes and records it as a known limitation and a 0.9 follow-up. Outside a session, Basic's tile, notification action and share still work.
2. **Licence finding, flagged for the controller: `libadb-android` needs `spake2-android` 2.2.1, which is LGPL-3.0 and ships prebuilt `libspake2.so` for four ABIs.** That is not Apache/MIT/BSD. LGPL-3.0 lets an Apache-2.0 app ship an unmodified, separately replaceable library with its licence and a source link. This plan's default is to do that, with the LGPL text in `docs/licenses.md` and a NOTICE line. The controller confirms or overrules this at the Task 2 review. The fallback is a Kotlin SPAKE2 (BoringSSL-compatible, with test vectors) behind the same `AdbClient`, as a separate task. F-Droid's view of JitPack and of prebuilt `.so` files is a recorded follow-up (srclib), not a blocker.
3. **Two helper patches,** both listed in `android/helper/UPSTREAM.md`:
   - **P1, peer check.** Each socket the helper accepts on `localabstract:scrcpy_<scid>` must come from uid 2000 (`shell`, which `adbd` runs as) or 0. Anything else is closed, and the helper accepts the next. ARCHITECTURE §6.2/§7 want the local socket protected by a token. The scid in the socket name is only 31 random bits, and any local app could race the app's connect and receive the screen.
   - **P2, sensitive clips.** Clipboard autosync skips clips whose description has `android.content.extra.IS_SENSITIVE = true` (Android 13+). SPEC §14 says concealed items are never sent, and in Full mode a password copied on the phone would otherwise land on the Mac pasteboard unasked.

   With the patches, the helper's version string is `5.0.1-am1`.
4. **`MirrorStart` also carries `session` and `port`, and `MirrorState` and `MirrorStop` carry `session`.**
   - A new start replaces the old one, and adaptive quality restarts the session. A late `STOPPED` from the old session must not close the new one.
   - SPEC §13 announces the bulk port only when a files feature is shared, and the port changes after wake.
5. **`mirror.state` has no `width`, `height` or `codec`.** The relay copies bytes without parsing them (decision 4). The stream's own session packets are the size, and they change on rotation. Two sources of the same fact would disagree.
6. **`mirror.start` has no `screen_off`.** The Mac sends `SET_DISPLAY_POWER` on the helper's control socket itself: at start (the setting), on the toolbar toggle, and "on" before every Mac-side stop. On any other ending, the helper's own cleanup process restores the display. The phone app has nothing to do with it.
7. **The test pattern is started with `am start` over the phone's own ADB link, on a new `mirror.test_pattern` message.** Android 10+ forbids an app from opening an activity from the background. The scrcpy control socket can only start an app's launcher activity.
8. **The ADB link stays open between sessions,** until the Mac disconnects or 10 minutes after the last session, and the last connect port is cached. Otherwise every adaptive-quality restart would repeat NSD discovery, which took seconds in the spike.
9. **Clipboard autosync follows the phone's existing "Share clipboard" switch:** `clipboard_autosync` is set from it at launch. The Mac also drops helper clipboard text while the phone's last `clipboard.availability` is off, which covers the switch turned off mid-session.
10. **Keyboard: every special key is a down and an up per Mac `keyDown`, repeats included.** Nothing is ever held on the phone, so focus loss can't strand a key. Cmd-Backspace (left open in the notes) is Shift+Move Home, then Delete.
11. Copy uses macOS title case ("Show Phone Screen", "Measure Delay…"). Build rulings continue the numbering from 0.4, starting at **R38**.

## Global Constraints

Everything in the 0.1–0.4 plans' Global Constraints still applies (platforms, licensing, TLS, identifiers, strings, accessibility, gating). In addition:

**Hard rules carried from 0.1–0.4** (from the design notes, word for word)
- Do NOT change ConnectionManager / PhoneSession / MacServer / ControlConnection logic. New channels, message types, bulk roles OK. BulkServer (0.3, ConnectionCore) MAY gain roles.
- SPEC §3 gating; phone: shared + user switch on + "permission" (here: Full mode armed); Mac R22: automatic Mac→phone streams gate on the phone's availability.
- Mac NotifyWork: never block the ordered stream; mirror video/audio/control bytes must NOT go through NotifyWork (they ride their own bulk links); only mirror.* control-channel messages do.
- Swift 6: no MainActor-isolated closure handed to a system API (VideoToolbox output callbacks, AudioQueue/AVAudioEngine taps, NWConnection handlers, NSEvent monitors) — build in nonisolated helpers.
- Never read SMS. No content in logs (no screen content, clipboard text, typed text, app names, window titles).
- Permissions/TCC only when the feature is turned on. Never unlocks the Mac.
- Apache-2.0; reuse scrcpy (Apache-2.0) with NOTICE/attribution; never KDE Connect code.

**Further rules for this milestone**
- **The spike code is throwaway.** Re-implement from this plan and from upstream scrcpy at tag v5.0.1; never copy files from `spike/full-mode`.
- **The phone app opens no listening socket** (no `ServerSocket`, `LocalServerSocket` or `bind`) in `android/app`, `feature/mirror` or `core/adb`. The relay goes only to the connected, paired Mac's bulk port, pinned by fingerprint (`BulkConnector`).
- **Logs:** on the Mac, `Logger(subsystem: "io.github.anmirror.mac", category: "mirror")`; on the phone, tag `Mirror`. Log session IDs, phases, reason and enum names, sizes, codecs, presets, fps, delays and byte counts only. The helper's output lines are read to classify failures and are never logged. The stream's device name counts as content.
- **Mac permissions:** Full mode needs no new TCC grant. Input goes to the mirror view's own window; no Accessibility, Screen Recording or microphone.
- **Android manifest:** no new permissions. New components: `PairingReplyReceiver`, `MirrorStopReceiver` and `mirror.DelayTestActivity`, all `exported="false"`.
- **Phone switch:** prefs file `mirror`, key `allow_mirror`, **default off**. Copy: "Allow your Mac to show this screen".

**scrcpy v5.0.1 wire format** (the Mac parses it; `protocol/vectors/scrcpy.json` is the authority, cross-checked against the vendored server in Task 2)
- **Video socket, helper → Mac:** one dummy byte `0x00`; the device name, 64 bytes, UTF-8, NUL-padded; the codec ID, u32 BE (`h264` = `0x68323634`, `h265` = `0x68323635`); then packets. Each packet starts with a 12-byte header:
  - Byte 0 bit 7 set: a **session packet**; bytes 4–7 are the width and 8–11 the height (u32 BE), with no payload.
  - Otherwise: bytes 0–7 are a u64 BE where bit 62 = config, bit 61 = key frame and the low 61 bits = PTS in µs; bytes 8–11 are the payload size (u32 BE). Then the payload, in Annex B.
- **Audio socket:** the codec ID, u32 BE (`opus` = `0x6f707573`, `aac ` = `0x00616163`; `0` = the phone can't capture audio, `1` = error), then the same media packets, with no session packets.
- **Control socket, Mac → helper** (type byte first, all BE):
  - `0` INJECT_KEYCODE: u8 action, u32 keycode, u32 repeat, u32 meta state.
  - `1` INJECT_TEXT: u32 length + UTF-8, at most 300 bytes.
  - `2` INJECT_TOUCH_EVENT: u8 action, u64 pointer ID, i32 x, i32 y, u16 width, u16 height, u16 pressure (0xFFFF = 1.0), u32 action button, u32 buttons.
  - `3` INJECT_SCROLL_EVENT: i32 x, i32 y, u16 width, u16 height, i16 hscroll, i16 vscroll (`clamp(v / 16, −1, 1) × 32768`, clamped to −32768…32767), u32 buttons.
  - `4` BACK_OR_SCREEN_ON: u8 action.
  - `8` GET_CLIPBOARD: u8 copy key (0 none, 1 COPY, 2 CUT).
  - `9` SET_CLIPBOARD: u64 sequence, u8 paste, u32 length + UTF-8, at most 262,130 bytes.
  - `10` SET_DISPLAY_POWER: u8 on.
  - `11` ROTATE_DEVICE.
  - `17` RESET_VIDEO.
  - The type numbers above 4 are confirmed from the vendored `ControlMessage.java` in Task 2. The fixtures are fixed if they differ.
- **Control socket, helper → Mac:** `0` CLIPBOARD (u32 length + UTF-8), `1` ACK_CLIPBOARD (u64 sequence), `2` UHID_OUTPUT (u16 id, u16 size, data; skipped).
- **The touch pointer** is the generic finger, ID −2 (`0xFFFFFFFFFFFFFFFE`). Buttons and the action button are 0. The width and height must equal the current video size.

**Helper launch** (phone)
- **The jar:** asset `anmirror-helper.jar`, pushed to `/data/local/tmp/anmirror-helper.jar` before every session with `exec:cat > <path>`, then checked with `sha256sum` against `BuildConfig.HELPER_SHA256` (20 tries, 200 ms apart). `cleanup=true` makes the helper delete it on exit.
- **The command, exactly** (one line; `<…>` are the session's values):
  `CLASSPATH=/data/local/tmp/anmirror-helper.jar app_process / com.genymobile.scrcpy.Server 5.0.1-am1 scid=<8 lowercase hex> log_level=warn tunnel_forward=true video=true audio=<true|false> control=true video_codec=<h264|h265> audio_codec=<opus|aac> max_size=<n> video_bit_rate=<n> max_fps=<n> clipboard_autosync=<true|false> cleanup=true power_off_on_close=false`
- **scid:** random, `0…0x7FFFFFFF`, 8 lowercase hex digits. The socket is `localabstract:scrcpy_<scid>`.
- **Before launching,** run `pkill -f anmirror-helper.jar` (never a pattern that would match a computer-launched scrcpy).
- **Socket order:** video, then audio (only when `audio`), then control. Retry each open every 100 ms for up to 5 s. The video socket counts as open once its dummy byte is read; that byte is forwarded to the Mac.

**Timing and limits**
- **Phone:**
  - NSD looks for `_adb-tls-pairing._tcp` for 6 s and `_adb-tls-connect._tcp` for 5 s.
  - The ADB connect timeout is 10 s. Hosts are tried as `127.0.0.1` first, then the NSD host.
  - A session must reach RUNNING within 20 s, or it ends FAILED.
  - The ADB link closes 10 min after the last session ends, and when the Mac disconnects.
  - **Relay:** a 65,536-byte buffer per direction, a flush after every write, blocking I/O, and no queue. The bulk socket's send buffer is set to 262,144 bytes.
- **Mac:**
  - The start deadline is 20 s, to `RUNNING` and a first decoded frame.
  - Bulk tokens follow SPEC §13: 32 bytes, single use, 60 s. Their context is `mirror-<session>`, and they are revoked when the session ends.
  - **Backlog:** with more than 30 undecoded packets, or a newest packet more than 500 ms late (`LatenessMeter`), the decoder drops everything up to the next key frame and sends RESET_VIDEO, at most once per second.
- **Quality presets:**

  | Preset | `max_size` | `video_bit_rate` | `max_fps` |
  |---|---|---|---|
  | High | 1920 | 8,000,000 | 60 |
  | Balanced | 1280 | 4,000,000 | 60 |
  | Low | 960 | 2,000,000 | 30 |

- **Auto quality** (the default):
  - It starts at High and is evaluated every 1 s.
  - **Step down** one preset when the median lateness over the last 5 s is > 150 ms, or the decode backlog stays > 6 frames for 5 s.
  - **Step up** after 60 s in which every evaluation had a median ≤ 75 ms and a backlog ≤ 6.
  - **Back-off:** a step-up followed by a step-down within 30 s doubles the next wait for that preset (60 → 120 → 240 → 480 → 600 s). It resets after 10 min at the higher preset.
  - A manual preset turns Auto off. A restart keeps the window and its last frame.
- **Audio:** PCM Float32, 48 kHz, stereo. The jitter target is 60 ms. Drop the oldest audio beyond 150 ms. After an underrun, wait for 40 ms before playing again.
- **Delay harness:**
  - 50 trials, each with a 3 s timeout and a 500 ms pause between trials.
  - Black = centre 32×32 mean luma < 50; white = > 200.
  - Then 30 s of frame counting.
- **Text:** INJECT_TEXT chunks are ≤ 300 bytes, cut at a Unicode scalar boundary. Cmd-V text is ≤ 262,130 bytes; longer gives `NSSound.beep()` and sends nothing.

**Android key and motion constants** (used by Task 6)
- **Key codes:** BACK 4, HOME 3, APP_SWITCH 187, VOLUME_UP 24, VOLUME_DOWN 25, ENTER 66, DEL 67, FORWARD_DEL 112, TAB 61, ESCAPE 111, DPAD_UP 19, DPAD_DOWN 20, DPAD_LEFT 21, DPAD_RIGHT 22, PAGE_UP 92, PAGE_DOWN 93, MOVE_HOME 122, MOVE_END 123, A 29, Z 54.
- **Meta states:** SHIFT = `0x1 | 0x40`, CTRL = `0x1000 | 0x2000`.
- **Actions:** key DOWN 0, UP 1; motion DOWN 0, UP 1, MOVE 2.

**Acceptance targets** (PRD F-17, ROADMAP 0.5 exit)
- **Delay:**
  - Measured by "Measure Delay" as the round trip: Mac tap → phone draws white → capture → encode → relay → Wi-Fi → Mac decode.
  - Pass: median < 80 ms on the reference phones over 5 GHz Wi-Fi.
  - A median from 80 to 120 ms needs the slow-motion film check (owner check (b)), as in the spike.
- **Frame rate:** ≥ 55 fps mean over 30 s at High.
- **Typing (including emoji) into WhatsApp works.**
- **Weaker links:** quality steps down rather than missing the delay target.

## Review Focus

These are the five failures a real person is most likely to hit that no feature test covers. Each one gets a test in the task named in brackets.

1. **A stuck finger.** Expected: no touch stays down on the phone after the Mac stops pressing. That covers:
   - the window losing focus mid-drag, or being closed;
   - the phone disconnecting, or Auto quality restarting the session, mid-drag;
   - the phone rotating mid-drag (the video size changes);
   - releasing the button outside the picture.

   Every one sends a touch UP at the last position first.

   *(Task 6 `resignKeyReleasesHeldTouch`, `windowCloseReleasesHeldTouch`, `sessionEndReleasesHeldTouch`, `sizeChangeMidDragReleasesFirst`, `upOutsidePictureClampsToEdge`, `repeatedKeyDownSendsPairEach`)*
2. **The session ending badly.** The cases: the Mac sleeps mid-mirror, Wi-Fi drops, a second start arrives while one runs, the helper crashes, Wireless debugging is turned off mid-session, the phone's switch is turned off, or the user taps Stop in the phone's notification. Expected:
   - The helper is stopped, and every link and pipe is closed.
   - The Mac shows why, and the tokens are revoked.
   - A late state from an old session never closes the new one.
   - The screen comes back on. That last one is an owner check: the helper's cleanup does it.

   *(Task 4 `secondStartReplacesFirst`, `macLinkEofStopsHelper`, `helperExitReportsHelperFailed`, `adbDropReportsAdbFailedAndNeedsSetup`, `switchOffStopsWithTurnedOff`, `disconnectStopsWithoutMessage`, `notificationStopTellsMac`; Task 5 `staleStateFromOldSessionIgnored`, `sleepStopsSession`, `disconnectClosesSessionAndRevokes`, `startTimesOutAfter20s`; Task 8 `stopTurnsScreenBackOnFirst`)*
3. **Lag piling up on a weak link.** Expected: the picture may get blurrier or skip frames, but it never trails seconds behind.
   - The phone relay never buffers more than one chunk, and flushes each one.
   - The Mac reads eagerly and drops to the next key frame (with RESET_VIDEO) when the backlog grows.
   - Auto quality steps down within about 6 s, and a short spike doesn't trigger it.

   *(Task 4 `relayFlushesEveryChunk`, `blockedOutputStopsReadingAfterOneChunk`; Task 5 `backlogDropsToNextKeyframeAndRequestsReset`; Task 9 `sustainedLatenessStepsDown`, `shortSpikeDoesNotStepDown`, `failedStepUpBacksOff`)*
4. **Typing that goes wrong.** The cases: a Japanese or Chinese input method mid-composition, emoji from the Character Viewer, Hindi or Russian text, a paste of a long message, Cmd-W expecting to close the window, or an emoji typed while the Mac clipboard holds something else. Expected:
   - Composing text is shown but not sent until committed.
   - ASCII goes as text injection; everything else goes as one paste.
   - Long text is split at a scalar boundary.
   - Cmd-W closes the window and reaches nothing on the phone.
   - A typed emoji never shows up on the Mac's pasteboard.

   *(Task 6 `markedTextIsNotSent`, `asciiGoesAsInjectText`, `emojiGoesAsClipboardPaste`, `nonLatinGoesAsPaste`, `longTextSplitsAt300BytesOnScalarBoundary`, `cmdWClosesAndIsNotForwarded`, `pasteOverLimitIsRefused`; Task 8 `typedEmojiPasteIsNotCopiedBack`, `helperEchoOfMacCopyIsIgnored`)*
5. **Setup mistakes.** The cases: the user types the Wireless debugging (connect) port instead of the pairing port, an old or mistyped code, the pairing screen closed before the code was sent, or a phone whose NSD never finds the pairing service (the vivo in the spike). After a reboot Wireless debugging is off, or the connect port changed. Expected:
   - Each mistake gets its own clear message.
   - The reply format asks for the port when NSD found none.
   - Availability says NEEDS_SETUP until a connect succeeds, and a cached port is tried before NSD.

   *(Task 3 `connectPortGivesWrongPort`, `handshakeFailureGivesWrongPort`, `failureAfterHandshakeGivesWrongCode`, `refusedGivesNotListening`, `replyWithoutPortUsesDiscovered`, `noPortKnownNeedsBoth`, `wirelessDebuggingOffNeedsSetup`, `connectFailureNeedsSetupUntilSuccess`, `cachedPortTriedBeforeNsd`, `nsdMissingFallsBackToTypedPort`)*

**Rules:**
- **`mirrorAvailability`,** in this order:
  - `sdk < 30` → UNAVAILABLE.
  - `!userOn` → OFF_BY_USER.
  - `!paired` → NEEDS_SETUP.
  - `wirelessDebugging == false` → NEEDS_SETUP.
  - `lastConnectFailed` → NEEDS_SETUP.
  - Else enabled. `null` (unreadable) never blocks.
- **`mirrorOpen()`** = `mirror.v1` shared && the availability is enabled.
- **`PairingReply`:**
  - The code is exactly 6 ASCII digits. The port is 1–65535, separated by whitespace or `:`.
  - A bare code needs `discoveredPort`.
  - Surrounding whitespace is trimmed. Anything else is `Invalid`.
- **`PairingErrors.classify`:**
  - The port equals `knownConnectPort` → WRONG_PORT.
  - `AdbPairingException` stage NOT_LISTENING (connection refused) → NOT_LISTENING; HANDSHAKE (an `SSLException` before the pairing exchange) → WRONG_PORT; AFTER_HANDSHAKE → WRONG_CODE.
  - A timeout → TIMEOUT.
  - `LibAdbClient` sets the stage from where its pairing failed. The builder confirms the mapping on the owner's phone in owner check (a) and records the exception classes seen.
- **`MakerGuidance.of`** (lowercased `Build.MANUFACTURER`):
  - `xiaomi`, `redmi`, `poco` → USB_DEBUGGING_SECURITY.
  - `oppo`, `oneplus`, `realme`, `vivo`, `iqoo` → DISABLE_PERMISSION_MONITORING.
  - Else NONE.
- **`FullModeSetup`:**
  - **Identity:** created once on the first `startPairing`, stored encrypted, never logged, and excluded from backup.
  - **Pairing:**
    - `pair` uses `127.0.0.1`, then the NSD host.
    - After a successful pair, it records `paired` and connects. A connect success clears `lastConnectFailed` and stores `lastConnectPort`.
    - The notification is posted by `notify` and cancelled on success. A failure re-posts it with the error line in the notification's text.
  - **`ensureConnected`:**
    - Returns at once when the client is connected.
    - Otherwise tries the cached port, then NSD connect, then `typedPort`.
    - A failure sets `lastConnectFailed`, which makes the availability NEEDS_SETUP.
  - **Re-arm:** "Re-enable Full mode" opens `Settings.ACTION_APPLICATION_DEVELOPMENT_SETTINGS` with the extra `":settings:fragment_args_key" = "toggle_adb_wireless"` (plain developer settings if that throws). `MainActivity.onResume` then calls `ensureConnected()`.
